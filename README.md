# TPMBOOT 0.2.0-demo

Для руководства: [docs/MANAGEMENT_OVERVIEW_RU.md](docs/MANAGEMENT_OVERVIEW_RU.md).

Полная инструкция: [docs/DEMO_GUIDE_RU.md](docs/DEMO_GUIDE_RU.md).

Демонстрационный релиз: x86-64 UEFI + TPM 2.0, VMware Workstation, Debian 13.
Проверенный ранее стенд: ядро 6.12.113+deb13-amd64, LSI mptspi, ESP /dev/sda1,
корень ext4 UUID=28fa6bbe-177e-422d-a88e-559ebe08777d. Secure Boot выключен.

Это демонстрация со случайным 64-байтовым секретом, не production-релиз.
Режим --debug-secret раскрывает тестовый секрет в консоли. Сам секрет не входит
в распространяемый архив. Закрытых ключей, TPM state и готового EFI с чужим ключом нет.

## Первая установка: создание ключей

При отсутствии прежних ключей выполните без sudo:

```sh
bash scripts/generate-keys.sh
```

При существующем keys/ скрипт ничего не заменяет. Для обновления используйте прежние ключи.

## Обновление существующего проекта

Распакуйте архив в отдельный каталог. Скопируйте прежний каталог keys/ в корень
нового проекта (signing.key и public.bin). Не генерируйте новые ключи без необходимости.
Выполняйте команды из нового каталога проекта, в обычном Debian, не в RAM shell.

Зависимости Debian (если уже установлены, повторять не нужно):

```sh
sudo apt install build-essential python3 file kmod zstd xz-utils busybox-static tpm2-tools efibootmgr
```

Нужен Rust/Cargo через rustup. Сборка EFI выполняется под вашим пользователем:

```sh
bash scripts/build-demo.sh
bash scripts/install-demo.sh --reenroll
sudo reboot
```

ЭТИ ЖЕ команды можно выполнять при каждой новой демонстрационной сборке.
Имена менять не нужно. Используются постоянные demo/vmlinuz.efi,
demo/initramfs.img, demo/manifest.bin, demo/tpmboot.efi и demo/public.bin.
build-demo.sh включает hex-вывод по умолчанию; --no-debug-secret отключает его.
Для подготовки без пересборки Rust используйте sudo python3 scripts/demo.py prepare --debug-secret.
Не перезагружайтесь, если какой-либо шаг завершился ошибкой.

prepare собирает во временном каталоге, проверяет подписанный комплект и
заменяет demo/ только после успеха. Предыдущая сборка сохраняется в demo-backups/.
install --reenroll сохраняет прежний ESP-каталог вместе с sealed.bin в уникальном
/var/backups/tpmboot-demo/install-*/TPMBOOT, проверяет копию, затем устанавливает
новый комплект с enroll.request. На следующей загрузке создаётся НОВЫЙ СЛУЧАЙНЫЙ
ТЕСТОВЫЙ СЕКРЕТ. Это не миграция прежнего секрета. TPM не очищается.

Без --reenroll команда install сохраняет установленный секрет, если комплект
побайтно совпадает; если комплект изменён, останавливается с объяснением.
Повторная регистрация никогда не запускается молча.

Для другой разметки задайте параметры prepare явно:

```sh
sudo python3 scripts/demo.py prepare --debug-secret --esp-device /dev/sda1 --root-uuid UUID-КОРНЕВОГО-EXT4
```

Путь к ESP при install по умолчанию /boot/efi, меняется через --esp.
Скрипт установки не перезагружает машину автоматически.
BootOrder и запись TPMBOOT-LAB остаются прежними; установщик их не изменяет.
На новой VM нужно отдельно создать EFI-запись (см. docs/WINDOWS_VMWARE.md).

## Демонстрация

1. EFI проверяет подписанный комплект и передаёт снимок ранних PCR в initramfs.
2. Первый запуск печатает BEFORE sealing: 4 строки по 16 байт, ждёт 30 секунд,
   запечатывает случайный секрет TPM, сохраняет sealed.bin и перезагружает VM.
3. Следующий запуск EFI распечатывает секрет и передаёт его в RAM-initramfs.
4. Потребитель печатает AFTER unsealing в том же hex-формате и проверяет SHA-256.
5. PASS, удаление файла передачи, 30 секунд паузы, запуск Debian через switch_root.
6. Следующие загрузки повторяют пункты 3–5, без регистрации.

Без --debug-secret hex не печатается. Пауза после PASS остаётся 30 секунд.
Вывод секрета расположен в scripts/vmware-lab.py; build-info.json фиксирует режим.
Политика доверяет целому подписанному initramfs. Корневой ext4 Debian не аутентифицирован,
не зашифрован этим проектом и не защищён от подмены. /home и swap монтирует Debian по fstab.
Секрет используется тестовым потребителем и не передаётся сервису установленной ОС.
Минимальный initramfs не заменяет все функции штатного Debian initramfs (например fsck,
resume, LUKS/LVM); этот профиль предназначен для показанной простой ext4-разметки.

## Откат

Выключите VM и выберите VMware VM > Power > Power On to Firmware > debian.
В /var/backups/tpmboot-demo найдите нужный install-* (скрипт печатает точный путь).
Восстановите ВЕСЬ его каталог TPMBOOT вместо /boot/efi/EFI/TPMBOOT: загрузчик,
ядро, initramfs, manifest и sealed.bin должны быть от одной версии. Сначала
сохраните текущий каталог отдельно. Не смешивайте старый sealed.bin с новым EFI.
Не очищайте TPM и не удаляйте vTPM для отката. Сбой питания между двумя rename
может потребовать ручного восстановления из резервной копии; установка не является
атомарной относительно отключения питания. При ошибке скрипт печатает staging-путь.

## Исправления

- Размер TPM-ответа ограничен GetCapability.max_response_size; UEFI статус виден.
- NOT_FOUND при поиске чужого LoadFile2 означает отсутствие конфликта.
- Сообщение EFI-ошибки удерживается 60 секунд.
- mptspi с зависимостями, nls_ascii и ext4 включены в initramfs.
- write_new корректно обрабатывает имя без каталога; CLI сохраняет create-only.
- Постоянные имена собираемых файлов, автоматические резервные копии.
- Hex-демонстрация и переход в Debian после 30 секунд.
