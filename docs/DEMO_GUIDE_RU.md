# TPMBOOT 0.2.0-demo: сборка и демонстрация

## Что демонстрируется

UEFI-загрузчик проверяет подписанные ядро и initramfs. TPM 2.0 выдаёт 64-байтовый
секрет при совпадении заданной политики PCR. Программа в initramfs получает секрет,
проверяет его длину и SHA-256, удаляет файл передачи. Через 30 секунд после PASS
запускается Debian без дополнительной перезагрузки.

Это демонстрационный прототип. Статус фактических проверок — RELEASE_VALIDATION.md,
ограничения защиты — SECURITY.md. Переход в Debian и вывод hex этого релиза ещё
нужно проверить на стенде. Корневой раздел Debian не аутентифицирован этим проектом.

## Среда

- Windows с VMware Workstation, VM x86-64, UEFI и vTPM 2.0.
- Secure Boot выключен. Для добавления vTPM используйте настройки шифрования VMware.
- Debian 13; Rust/Cargo через rustup установлен под обычным пользователем.
- Простые разделы ext4, без LUKS/LVM/RAID в демонстрационном профиле.
- Пример проверенного ядра: 6.12.113+deb13-amd64. В установленном Debian должны
  быть модули именно ядра, которое передаётся EFI-загрузчику.

Зависимости в Debian:

```bash
sudo apt update
sudo apt install -y build-essential curl ca-certificates python3 unzip file kmod \
  zstd xz-utils busybox-static tpm2-tools efibootmgr mokutil libtpms0
```

Если rustup ещё не установлен:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs -o /tmp/rustup-init.sh
sh /tmp/rustup-init.sh -y --profile minimal
. "$HOME/.cargo/env"
```

Распакуйте архив в Linux-файловую систему домашнего каталога, перейдите в каталог
`tpm-initrd-boot-demo`. Все последующие команды выполняются из него.

## Два разных секрета

| Объект | Назначение | Где находится |
|---|---|---|
| `keys/signing.key` | Закрытый seed Ed25519, 32 байта; подписывает манифест | На машине сборки |
| `keys/public.bin` | Публичный ключ Ed25519, 32 байта | Встраивается в EFI при сборке |
| Тестовый секрет, 64 байта | Данные, запечатываемые и выдаваемые TPM | Генерируется в RAM при регистрации |
| `sealed.bin` | TPM-контейнер тестового секрета | На EFI-разделе |

Скрипт генерации ключей не создаёт 64-байтовый секрет и не обращается к TPM.
Закрытый signing.key не копируется установщиком на EFI-раздел и не включается в initramfs.

## Ключи: новая установка

Только если у проекта ещё нет своей пары ключей:

```bash
bash scripts/generate-keys.sh
```

Скрипт собирает только host-утилиту initrdctl через Cargo, поэтому готовый EFI
для генерации не требуется. Создаёт каталог keys/ с правами 0700 и два файла
по 32 байта с правами 0600. Содержимое закрытого ключа не печатается.
При существующем keys/ скрипт останавливается, ничего не заменяя, даже если каталог пуст.
Резервную копию signing.key храните отдельно от демонстрируемой VM.

## Ключи: обновление существующего стенда

Если ключи уже были созданы в ~/tpm, не генерируйте новые. В свежем каталоге релиза:

```bash
test ! -e keys && cp -a ~/tpm/keys ./keys
```

Не удаляйте keys/ ради повторного запуска generate-keys.sh. Для обычной пересборки
генератор вообще не нужен. Ротация пары меняет доверенный EFI и требует отдельной
процедуры повторной регистрации; --reenroll создаёт новый случайный секрет, а не
сохраняет старый.

## Проверка параметров стенда

```bash
mokutil --sb-state
findmnt /boot/efi
findmnt -no SOURCE,FSTYPE /
lsblk -f
ls -l /dev/tpm*
```

Настройки по умолчанию соответствуют текущему стенду:

| Параметр | Значение |
|---|---|
| ESP | `/dev/sda1`, смонтирован в `/boot/efi` |
| UUID корня ext4 | `28fa6bbe-177e-422d-a88e-559ebe08777d` |
| Контроллер | LSI Logic Parallel SCSI, `mptspi` |
| Задержка после PASS | 30 секунд |

Для другой VM задайте её собственные параметры при сборке, не копируйте UUID примера.

## Сборка

```bash
bash scripts/build-demo.sh
```

Скрипт собирает EFI с вашим public.bin, статическую Linux-утилиту, initramfs с
драйверами, подписывает и проверяет комплект. sudo запрашивается только для
подготовки образа. Сам скрипт запускайте без sudo.

В этой команде hex-вывод включён. Для сборки без раскрытия секрета в консоли:

```bash
bash scripts/build-demo.sh --no-debug-secret
```

Для другой разметки:

```bash
bash scripts/build-demo.sh --esp-device /dev/sda1 --root-uuid ВАШ-UUID-КОРНЯ
```

Результат всегда в demo/. Имена не меняются. Предыдущий результат автоматически
сохраняется в demo-backups/. Низкоуровневый vmware-lab.py не предназначен для
перезаписи ранее созданного каталога: используйте build-demo.sh или demo.py prepare.

## Установка

После успешной сборки:

```bash
bash scripts/install-demo.sh --reenroll
```

Установщик проверяет подпись, сохраняет прежний EFI/TPMBOOT в уникальный каталог
`/var/backups/tpmboot-demo/install-*/TPMBOOT`, печатает его путь и устанавливает
новый комплект. --reenroll означает регистрацию НОВОГО СЛУЧАЙНОГО ТЕСТОВОГО СЕКРЕТА.
Не используйте этот режим для сохранения реального секрета или ключа зашифрованных данных.
TPM, его авторизации и BootOrder скрипт не изменяет. Автоматической перезагрузки
после команды установки нет.

Без --reenroll:

```bash
bash scripts/install-demo.sh
```

Если комплект совпадает, существующий sealed.bin сохраняется. При новом или
изменённом комплекте скрипт останавливается. Так повторная установка не инициирует
незаметную замену секрета.

## EFI-запись

На текущем стенде TPMBOOT-LAB уже существует — повторять создание записи не нужно.
На новой VM сначала проверьте:

```bash
sudo efibootmgr -v
```

Только для ESP /dev/sda1, если записи ещё нет:

```bash
sudo efibootmgr --create --disk /dev/sda --part 1 \
  --label TPMBOOT-LAB --loader '\EFI\TPMBOOT\tpmboot.efi'
sudo efibootmgr -v
```

TPMBOOT-LAB должен быть первым в постоянном BootOrder на обеих регистрационных
загрузках. Не используйте одноразовый BootNext для регистрации. Сохраните запись Debian.
Не перезаписывайте EFI/debian и EFI/BOOT. Номера записей индивидуальны для каждой VM.

## Запуск демонстрации

```bash
sudo reboot
```

1. При регистрации выводится BEFORE sealing: 4 строки по 16 байт в hex.
2. Пауза 30 секунд позволяет сфотографировать исходное значение.
3. Секрет запечатывается TPM, контейнер сохраняется, VM автоматически перезагружается.
4. EFI выдаёт секрет в initramfs; потребитель печатает AFTER unsealing.
5. Все 64 байта должны совпасть. Программа также проверяет SHA-256.
6. Выводится TPMBOOT LAB PASS; файл передачи удаляется.
7. Через 30 секунд initramfs монтирует ext4 по UUID и запускает Debian через switch_root.

При следующих загрузках выполняются пункты 4–7. /home и swap подключает Debian по
fstab. Получателем секрета остаётся тестовая программа внутри подписанного initramfs;
установленная ОС не получает отдельный файл с секретом от этого сценария.

## Повторная сборка без новых имён

```bash
bash scripts/build-demo.sh
bash scripts/install-demo.sh --reenroll
sudo reboot
```

Выполняйте следующую команду только после успеха предыдущей. keys/ не меняйте.
При изменении только Python-шаблона можно пропустить Rust-сборку:

```bash
sudo python3 scripts/demo.py prepare --debug-secret
bash scripts/install-demo.sh --reenroll
```

## Диагностика и откат

Для обычного Debian выключите VM и выберите VMware:
VM > Power > Power On to Firmware > debian (иногда через Boot Manager).
При аварийной оболочке и смонтированном ESP сначала выполните sync, umount /esp,
затем poweroff -f. Не очищайте TPM ради диагностики.

| Ошибка | Что проверить |
|---|---|
| GetCapability / SubmitCommand | Статус UEFI на экране, наличие vTPM |
| Нет ESP | Путь устройства, драйвер контроллера и его зависимости |
| IO charset ascii not found | Включён ли nls_ascii в установленный образ |
| Tpm(2337), 0x921 | DA lockout; `sudo tpm2_getcap properties-variable` |
| test already attempted | Незавершённая регистрация; не удаляйте контейнер вслепую |
| root UUID not found | UUID текущего ext4, параметры prepare |
| kernel modules missing | Совпадение версии ядра с /lib/modules установленной ОС |

Снятие DA lockout требует корректной авторизации lockout. Не повторяйте неудачные
авторизации и не применяйте tpm2_clear для исправления скриптов.

Для отката в Debian найдите путь резервной копии, который напечатал install-demo.sh.
Сохраните текущий EFI/TPMBOOT отдельно и восстановите ВЕСЬ прежний каталог TPMBOOT
из выбранной резервной копии. Важно восстановить вместе EFI, ядро, initramfs,
manifest.bin, public.bin и sealed.bin. Не смешивайте разные поколения файлов.
После sync перезагрузитесь обычным способом с исходным BootOrder.
Откат возможен только при сохранённом состоянии того же TPM и совместимых PCR.
Установка не атомарна при потере питания между переименованиями каталогов;
в этом случае восстановите каталог из резервной копии через обычный Debian.

## Тесты и ограничения

```bash
bash scripts/test.sh
```

TPM-тесты используют libtpms, не vTPM машины. Сценарии VMware подмены загрузочных
файлов и переноса на независимый TPM ещё требуют отдельного испытания.
Hex-режим раскрывает секрет в консоли, на фотографиях и видеозаписях.
Минимальный initramfs не реализует все функции штатного Debian initramfs:
fsck до монтирования, LUKS/LVM, resume и другие сценарии не входят в этот профиль.
