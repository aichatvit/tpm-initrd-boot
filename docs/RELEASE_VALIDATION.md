# Проверка 0.2.0-demo — 2026-10-27

Выполнено для этого исходного кода:

- Rust 1.99.1: release-сборка x86_64-unknown-uefi успешна.
- Release-сборка статического initrdctl x86_64-unknown-linux-musl успешна.
- cargo fmt и Clippy -D warnings: host + EFI успешны.
- 7 Rust unit tests успешны.
- 2 CLI integration tests успешны: подписи/подмена/другой ключ/create-only;
  регрессия записи выходного файла с именем без родительского каталога.
- 4 Python demo tests успешны: shell-синтаксис с debug вкл./выкл.; откат при
  ошибке rename; сравнение комплектов; требование reenroll, сохранение контейнера
  при идентичном комплекте и проверка резервной копии при замене.
- Python-синтаксис проверен.
- build-demo.sh и install-demo.sh: bash -n и запуск --help успешны.
  Полная установка этими оболочками на реальный ESP здесь не выполнялась.

Установочные тесты выполнялись в временных каталогах с имитацией mountpoint,
без обращения к реальному ESP и без изменений TPM. Новый initramfs на этом
исполнителе не собран: здесь нет ядра и модулей пользовательской Debian VM.
TPM-симулятор этого релиза повторно не запускался (libtpms отсутствует).
Предыдущие симуляторные проверки относятся к 0.1.0, TPM wire protocol не изменён.

Пользователь подтвердил для предыдущего комплекта с исправлениями: регистрация,
выдача прежнего 64-байтового секрета, повторный reboot и выключение/включение VMware.
Полная загрузка именно 0.2.0-demo с hex-выводом и switch_root в Debian пока НЕ проверена.
Это демонстрационный кандидат; не объявляется production-ready или проверенным
на физическом TPM. Не проверены в VMware отрицательные сценарии подмены/переноса.

В распространяемый архив не включены тестовые ключи, собранный с временным ключом EFI,
состояние TPM, dist/ и target/. Соберите EFI со своим прежним public.bin.

## Генератор ключей

generate-keys.sh: bash -n и --help успешны. В изолированной копии проверены
генерация реальной парой initrdctl, длины 32 байта, права 0700/0600 и отказ
повторного запуска без изменения ключей. В harness подменены Cargo-диспетчер
(использован ранее собранный initrdctl) и проверка UID; сами ключи генерировались
настоящей утилитой. На стенде пользователя скрипт ещё не запускался.
