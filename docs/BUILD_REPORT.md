# Проверка сборки — 26 октября 2026

В среде разработки выполнены:

- Rust stable 1.99.1, Cargo.lock из проекта.
- Сборка `efi-loader` release для `x86_64-unknown-uefi`.
- Сборка статического `initrdctl` release для `x86_64-unknown-linux-musl`.
- `cargo fmt --all -- --check`.
- Clippy с `-D warnings` для host crates и EFI target.
- 7 unit-тестов: форматы, усечение/лишние данные, подписи, хеши образов,
  CPIO-выдача секрета, PCR selection, некорректные TPM/PE-заголовки.
- CLI-интеграция: keygen/sign/verify, отказ при подмене ядра, initramfs,
  манифеста, ключа, запрет перезаписи и неявной регистрации.
- libtpms 0.9.3 через отдельный процесс, настоящие TPM 2.0 команды:
  CreatePrimary, StartAuthSession, PolicyPCR, PolicyCommandCode,
  PolicyGetDigest, Create, Load, Unseal, PCR_Read, PCR_Extend, FlushContext.
- Успешный sealing/unsealing 64 байт.
- Отказ TPM при изменении PCR и после закрытия фазы.
- Создание объекта для ранее записанных PCR, отличающихся от текущих.
- Моделируемый холодный перезапуск libtpms с сохранением permanent state:
  повторение цепочки открывает ранее созданный объект.
- Другая цепочка после перезапуска не открывает исходный объект.
- Новый независимый программный TPM не открывает скопированный объект.

Программные перезапуски не являются полной загрузкой QEMU/UEFI/Linux.
Запуск ядра через LoadFile2, работа на конкретной прошивке, интеграция с
конкретным initramfs и аппаратный TPM требуют приёмки отдельно.

Для проверки EFI использовался временный ключ сборки. Он не включён в проект.
Готовый EFI с этим ключом намеренно не распространяется: собирайте загрузчик
с вашим открытым ключом. В архив включена статическая Linux-утилита,
собранная из этих исходников; она не содержит ключей подписания.
